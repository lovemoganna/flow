Org Mode 笔记最小闭环：从记录到验证¶

2026-10-20 · Emacs / Org Mode / 知识管理

笔记的价值不在于保存多少文字，而在于能否支持下一步决策。本文给出一个可执行的最小流程：捕获、分类、执行、验证。重点是保留事实、判断与证据的边界。

四步工作流¶

  1. 捕获：记录问题、原始出处和时间。暂时不做结论。

  2. 分类：区分已确认事实、待验证判断和明确的下一步动作。

  3. 执行：每个待办只指定一个可观察的结果，不把行动描述成成果。

  4. 验证：记录实际检查结果；不满足条件就保留为未完成。

最小 Org 模板¶

以下示例为虚构的知识库维护任务。复制到一个 .org 文件，即可修改成自己的任务。

#+TITLE: 可追溯的笔记任务
#+DATE: 2026-10-20

* TODO 修复知识库中的失效链接
:PROPERTIES:
:SOURCE:   [[https://example.com/docs][原始页面]]
:END:
** 已确认事实
- 站内链接返回 404；记录检查时间与完整 URL。
** 待验证判断
- 可能由文件路径调整导致，尚未确认。
** 下一步动作
- 查询仓库路径，修复引用，并检查其他页面。
** 验收标准
- 目标链接可访问；站内链接检查无相关错误。

配置快速捕获¶

把下列配置放入 Emacs 初始化文件，并重新执行或重启 Emacs。

(require 'org)
(setq org-directory (expand-file-name "~/org"))
(make-directory org-directory t)
(setq org-default-notes-file
      (expand-file-name "inbox.org" org-directory))
(setq org-capture-templates
      `(("t" "任务" entry
         (file ,org-default-notes-file)
         "* TODO %?\n  %U\n  %a\n** 已确认事实\n** 待验证判断\n** 下一步动作\n** 验收标准\n")))
(global-set-key (kbd "C-c c") #'org-capture)

按 C-c c，选择 t 输入任务，按 C-c C-c 保存。任务写入 ~/org/inbox.org。路径可以按需修改。

验收方法¶

  1. 输入一个任务并保存，检查 inbox.org 是否出现对应标题。

  2. 检查任务是否有来源、已确认事实、待验证判断及验收条件。

  3. 实际完成后附上检查结果；没有证据时，不标记为已验证。

  4. 把复用价值较高的结论整理成独立笔记，保留原始任务链接。

退出条件：任务状态有依据，引用能打开，未解决的问题仍能被检索到。没有达到这些条件，不把笔记视为完成。
